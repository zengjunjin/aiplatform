RAG 平台技术白皮书（质量回归专用 golden 文档）。
本文档按主题分节撰写，覆盖质量回归 golden QA 集的全部知识点，
用于验证检索召回与生成忠实度的端到端质量。

第一节：RAG 核心组件。
检索增强生成系统的核心组件包括检索、生成、嵌入与向量四个部分。
检索组件负责从知识库中找出与问题相关的文档片段；
生成组件即大语言模型，基于检索到的上下文产出最终回答；
嵌入组件把文本编码为向量表示，是语义检索的基础；
向量组件则承担向量存储与相似度计算。
四个组件串联成"查询理解、向量召回、上下文组装、答案生成"的完整链路。

第二节：向量数据库的作用。
向量数据库是专门存储与检索向量的数据库系统，在 RAG 中承担语义记忆的角色。
文本经嵌入模型编码后写入向量数据库，查询时以向量相似度（如余弦相似度）
找出语义最接近的文档块。本平台采用 Qdrant 作为向量数据库，
支持高性能的近似最近邻检索、过滤条件与负载均衡，
使大规模知识库下的相似检索仍能在毫秒级完成。

第三节：文档分块策略。
分块（chunking）策略决定文档如何切分为可检索的片段。
常用策略包括固定大小分块（按字符数或 token 数）、
语义分块（按句子或段落边界）、递归分块（多级分隔符逐层切分）。
块大小与重叠是两个关键参数：块过大会稀释语义并消耗上下文预算，
块过小会割裂完整语义；相邻块之间保留一定重叠可以避免
关键句恰好落在边界上被割裂。本平台默认块大小 512 字符、重叠 50 字符。

第四节：RAG 质量评估。
RAG 系统的回答质量通过 RAGAS 框架评估，核心指标包括
faithfulness（忠实度，衡量答案是否被检索上下文支撑）、
context_recall（上下文召回率，衡量检索是否覆盖参考答案）、
answer_relevancy（答案相关性）与 context_precision（上下文精确度）。
评估流程将问题、答案、检索上下文与参考答案组成数据集，
由评估模型逐项打分，形成可回归对比的质量基线指标。

第五节：Prompt 模板版本化。
Prompt 模板版本化带来的好处包括：可以追踪每次提示词修改的历史记录，
出现质量回退时支持一键回滚到历史版本，便于开展 A/B 对比实验，
以及模板变更与代码发布解耦。版本化管理让提示词像代码一样
可评审、可审计、可恢复，是提示词工程走向工程化的关键基础设施。

第六节：上下文窗口管理。
上下文窗口管理策略用于在有限的 token 预算内组织对话历史与检索上下文。
常用策略包括：滑动窗口（只保留最近 N 轮对话）、
摘要压缩（将早期历史压缩为摘要后再拼入上下文）、
预算分配（为系统提示、检索上下文、历史对话分别划定 token 预算），
以及在超预算时按优先级裁剪最早或最不相关的内容。

第七节：Embedding 缓存。
Embedding 缓存通过把已计算过的文本向量存入 Redis，
在相同或相似文本再次请求嵌入时直接命中缓存，
避免重复调用嵌入模型。缓存命中可以显著降低嵌入计算的延迟与开销，
提升高并发场景下的检索性能，同时减轻模型服务的负载压力。

第八节：混合检索。
混合检索（hybrid retrieval）同时使用向量检索与 BM25 关键词检索两路召回：
向量检索负责语义层面的相似匹配，能够理解同义表达；
BM25 负责精确术语命中，擅长专有名词与关键字符匹配。
两路结果按倒数排名融合（RRF）算法合并为统一排序，
兼顾语义泛化能力与术语精确性，显著优于任何单路检索。

第九节：重排序的作用。
重排序（reranking）在粗召回之后对候选文档进行精排。
召回阶段为追求效率使用轻量模型快速筛出较大候选集，
重排序阶段则用交叉编码器逐对计算查询与文档的相关性分数，
依据精细的相关性重新排序并截取前 K 条。
重排序显著提升进入生成上下文的文档质量，是回答质量的重要保障。

第十节：聊天历史摘要压缩。
聊天历史的摘要压缩机制用于控制长对话的上下文长度：
当历史轮次超过阈值时，将较早的对话交给模型压缩为要点摘要，
摘要替代原始历史拼入上下文，近期轮次则保留原文。
这样既保住了长对话的关键信息，又把历史占用的 token 控制在预算内。

第十一节：知识库权限模型。
知识库平台的权限模型分为系统与知识库两级。
系统角色包括管理员与普通用户：管理员负责用户管理与平台运维，
普通用户在授权范围内使用平台功能。
知识库层面，创建者为所有者，可邀请协作者并授予只读或读写权限；
所有数据访问都经过所有权或协作者权限校验，确保数据隔离。

第十二节：SSE 流式响应与取消。
问答接口采用服务器推送事件（SSE）流式返回，回答逐字推送到前端。
当用户中途停止提问或关闭页面时，前端通过 AbortController
中断 EventSource 连接，服务端侦测到连接断开后取消后续生成任务，
释放模型推理资源，避免无人消费的无效计算继续占用算力。

第十三节：文档解析格式。
文档解析支持多种格式：PDF 通过版面分析抽取正文与表格，
Markdown 与 TXT 直接按文本处理，DOCX 解析段落与样式，
图片型文档走 OCR 识别。解析管线会做格式识别、文本抽取、
清洗规范化，再进入语义切分阶段，不同格式最终统一为标准文档块。

第十四节：RAG 延迟监控。
RAG 系统的延迟通过指标采集体系监控：解析、检索、重排序、生成
各阶段耗时以直方图指标暴露，由 Prometheus 抓取聚合，
配合 Grafana 看板展示 p50/p95/p99 分位延迟，
并配置告警规则在延迟超阈值时通知运维，实现性能问题的快速定位。

第十五节：模型路由策略。
模型路由（model routing）策略决定请求分发给哪个模型执行：
基于负载的路由把请求导向空闲实例，基于能力的路由按任务难度
选择合适规模的模型，fallback 降级策略在主模型不可用或超时时
自动切换到备用模型，保证服务持续可用。路由层还负责
配额管理与灰度发布，是新模型安全上线的前置关卡。
