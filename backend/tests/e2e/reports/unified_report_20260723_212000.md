## 六、P0 问题修复验证（2026-07-23 21:44 追加）

### 修复概要

针对批次五 E2E 测试的 23 failed + 20 error，开展了两项 P0 排查与修复，并重跑批次五验证。

### P0-1: admin 认证/授权异常（13 个 failed）

**根因**: 集成测试 `tests/integration/conftest.py` 的 `clean_db` fixture（autouse=True, function scope）在每个集成测试前后执行 `TRUNCATE TABLE ... users RESTART IDENTITY CASCADE`，导致批次四（集成测试）完成后 users 表被清空，admin 用户消失。E2E 测试启动时 admin 登录返回 401；`RESTART IDENTITY` 使新注册 testuser 获 id=1，与旧 admin token 的 sub="1" 冲突，导致 `test_get_me` 返回 testuser 而非 admin。

**辅助因素**: 191 个陈旧 `auth:blacklist:*` Redis 键（前次测试遗留）。

**修复措施**:
1. 执行 `INITIAL_ADMIN_PASSWORD=admin123 poetry run python init_db.py` 重建 admin 用户（id=1, role="admin"）
2. 清除 191 个陈旧 `auth:blacklist:*` Redis 键
3. 未修改任何业务代码（get_admin_user / auth_service / fixture 逻辑均正确）

**验证**: admin 登录 200 + GET /users 200 + GET /system/status 200 + GET /evaluation/runs 200 + GET /chat/feedback/stats 200 + POST /auth/refresh 200 + 旧 refresh_token 复用返回 401（单次使用生效）

### P0-2: KB 创建 500 错误（20 个 error + 2 failed）

**根因**（三个问题叠加）:
1. **Alembic 迁移 022 revision ID 超长**: `022_evaluation_created_by_ondelete`（34 字符）超出 `alembic_version.version_num` 列的 `varchar(32)` 限制，导致 `alembic upgrade head` 失败，数据库卡在 021，产生 schema 漂移
2. **集成测试 TRUNCATE users 表**（同 P0-1 根因）
3. **Redis 用户缓存导致 500**: `get_current_user` 优先查 Redis `user:{id}` 缓存（TTL 60s）；当 admin 被 TRUNCATE 但 Redis 缓存仍命中时，`get_current_user` 返回缓存用户 → `create_kb` 的 `db.commit()` 因 `owner_id` FK 约束失败 → 未捕获的 `IntegrityError` → 500

**修复措施**:
1. 修改 `backend/alembic/versions/022_evaluation_created_by_ondelete.py` 的 `revision` 从 `'022_evaluation_created_by_ondelete'`（34 字符）改为 `'022_eval_created_by_cascade'`（26 字符）
2. 同步更新 `backend/alembic/versions/023_evaluation_result_created_at.py` 的 `down_revision` 为 `'022_eval_created_by_cascade'`
3. 执行 `alembic upgrade head` 成功：021 → 022 → 023，schema 漂移修复
4. 清除 Redis DB 0 的 `user:*`（陈旧用户缓存）和 `rl:*`（限流计数器）键

**验证**: POST /api/v1/knowledge-bases 返回 200（KB id=1 创建成功）+ DELETE /knowledge-bases/1 返回 200 + alembic current = 023 (head)
