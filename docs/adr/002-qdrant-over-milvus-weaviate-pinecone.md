# ADR-002: 选择 Qdrant 而非 Milvus/Weaviate/Pinecone 作为向量数据库

## 状态

已采纳

## 日期

2026-07-04

## 上下文

RAG 系统的核心组件之一是向量数据库，用于存储文档 chunk 的 embedding 向量并执行相似度检索。需要在主流向量数据库中选择一个适合项目规模和部署环境的方案。

关键约束：
- 项目初期为本地开发/小规模部署，不希望引入过重的运维负担
- 需要支持混合检索（向量 + 标量过滤）
- 希望本地部署友好，不依赖云服务
- 性能需满足实时检索需求（毫秒级响应）

## 决策

选择 **Qdrant** 作为向量数据库。

核心理由：
1. **Rust 实现，性能优异**：内存效率和检索速度优于 Python 实现的同类产品
2. **轻量级部署**：单二进制文件，无需额外依赖（如 etcd、MinIO），Docker 一键启动
3. **本地部署友好**：支持本地文件持久化模式，无需配置分布式集群
4. **内置标量过滤**：原生支持 payload 过滤，可与向量检索组合使用
5. **API 设计简洁**：REST + gRPC 双协议，Python 客户端友好

## 后果

### 正面影响

- 部署简单，Docker 单容器即可运行，无额外运维负担
- 检索性能优秀，毫秒级响应
- 内置标量过滤，方便按知识库 ID 等维度过滤
- 本地持久化模式适合开发和小规模生产

### 负面影响

- 社区规模小于 Milvus，文档和案例相对较少
- 分布式能力不如 Milvus（但当前项目不需要）
- 部分高级功能（如 DiskANN）需企业版

## 替代方案

| 方案 | 优点 | 缺点 | 为何未选择 |
|------|------|------|------------|
| Milvus | 功能全面、分布式能力强、社区活跃 | 部署复杂（需 etcd + MinIO），资源占用高，对本地开发不够友好 | 过重，本地开发部署成本高 |
| Weaviate | 内置向量化模块、GraphQL 接口、AI-native | Java 生态（Go 实现但内存占用大），模块化引入额外复杂度 | 本地部署资源占用较大 |
| Pinecone | 全托管、零运维、自动扩缩容 | 云服务、不可本地部署、成本随规模增长、数据出境风险 | 不可本地部署，不符合项目需求 |
| Chroma | 极致轻量、Python 原生、AI-native | 生产环境成熟度不足，持久化可靠性存疑 | 不适合生产环境 |
