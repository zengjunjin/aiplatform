## 1. 平台简介

### 1.1 什么是 RAG 知识库平台

RAG（Retrieval-Augmented Generation，检索增强生成）知识库平台是一个企业级的智能问答系统，结合了大语言模型（LLM）与私有知识库，让 AI 基于您提供的文档资料给出准确、可追溯的回答。

**核心价值**：

- **私有知识 + AI 能力**：上传企业文档，AI 基于这些文档回答问题，避免幻觉
- **引用可追溯**：每个回答都标注来源文档与段落，可信可查
- **多格式支持**：PDF / DOCX / Markdown / TXT 文档一键导入
- **本地化部署**：所有数据留在内网，LLM 通过 Ollama 本地推理，不外泄
- **桌面客户端**：原生 Windows 桌面应用，深度链接、托盘、快捷键一应俱全

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 知识库管理 | 创建、配置、协作、删除知识库 |
| 文档管理 | 上传、解析、预览、删除文档 |
| 智能问答 | 流式对话、引用来源、上下文管理 |
| 评估系统 | RAGAS 自动评估 RAG 质量（忠实度/相关性/上下文精度/召回） |
| 反馈系统 | 用户对回答点赞/点踩，反馈统计可视化 |
| 用户管理 | 管理员管理用户、角色（RBAC） |
| 系统监控 | Grafana/Prometheus/Jaeger 实时监控（管理员） |

### 1.3 角色权限

| 角色 | 权限 |
|------|------|
| **admin（管理员）** | 所有功能 + 用户管理 + 系统监控 + 所有知识库 |
| **editor（编辑者）** | 创建知识库、上传文档、邀请协作者、聊天、评估 |
| **viewer（查看者）** | 查看被授权的知识库、聊天、提交反馈 |

### 1.4 技术栈（简版）

- **后端**：FastAPI + Python 3.12 + PostgreSQL + Redis + Qdrant + Celery
- **前端**：React 18 + Vite + Ant Design 5
- **AI**：Ollama（本地 LLM：qwen2.5:1.5b；Embedding：bge-m3；Reranker：bge-reranker-base）
- **桌面端**：Tauri 2（Rust + WebView2）
- **可观测性**：Prometheus + Grafana + Jaeger + Loki + Alertmanager

## 2. 快速开始

### 2.1 访问平台

#### Web 端

- 打开浏览器，访问 `http://<server-ip>:80/`（生产域名同理）
- 首次访问会跳转到登录页

#### Tauri 桌面客户端

- 安装 `RAG 知识库平台_0.2.0_x64-setup.exe`
- 启动后自动打开登录窗口
- 详见 [§4 Tauri 桌面客户端使用](#4-tauri-桌面客户端使用)

### 2.2 登录

1. 在登录页输入用户名 / 密码
2. 默认管理员账号（首次部署时通过 `init_db.py` 创建）
3. 登录成功后跳转到首页（Dashboard）

> **首次登录建议**：立即修改默认密码（点击右上角头像 → 个人设置 → 修改密码）

### 2.3 创建第一个知识库

1. 左侧导航点击 **"知识库"**
2. 点击右上角 **"+ 新建知识库"**
3. 填写名称（如"产品文档库"）、描述、选择 embedding 模型
4. 点击 **"创建"**

### 2.4 上传第一份文档

1. 进入刚创建的知识库
2. 切换到 **"文档"** 标签
3. 点击 **"上传文档"**，选择 PDF / DOCX / MD / TXT 文件
4. 等待解析完成（状态从 pending → parsing → chunking → embedding → done）
5. 解析完成后即可在聊天中提问

### 2.5 第一次问答

1. 左侧导航点击 **"聊天"**
2. 点击 **"+ 新建会话"**，选择关联的知识库
3. 在输入框输入问题，例如："这份文档的核心要点是什么？"
4. 系统会流式返回答案，并在答案下方标注引用来源

### 2.6 提交反馈

- 在助手回答下方，点击 **👍 点赞** 或 **👎 点踩**
- 可选填写评论说明
- 反馈数据将用于评估 RAG 质量

## 3. 功能模块说明

### 3.1 知识库管理

#### 3.1.1 创建知识库

1. 进入 **知识库** 页面
2. 点击 **+ 新建知识库**
3. 配置项：

| 字段 | 说明 | 示例 |
|------|------|------|
| 名称 | 知识库显示名 | 产品手册库 |
| 描述 | 简短描述 | 公司产品手册与技术规范 |
| Embedding 模型 | 文本向量化模型 | bge-m3（默认） |
| Chunk Size | 文档分块大小 | 512（默认） |
| Chunk Overlap | 分块重叠 | 50（默认） |
| 最大文档数 | 上限控制 | 100（默认） |

4. 点击 **创建** 后即可上传文档

#### 3.1.2 配置知识库

进入知识库详情页后，点击 **"设置"** 标签：

- **基础信息**：修改名称、描述
- **协作者管理**：邀请其他用户协作（详见 3.1.3）
- **高级配置**：调整检索参数（top_k、rerank 模型等）
- **删除知识库**：仅 owner 或 admin 可操作（删除后 30 天内可恢复）

#### 3.1.3 协作者管理

1. 进入知识库 → 设置 → 协作者
2. 点击 **+ 添加协作者**
3. 输入用户名，选择角色（editor / viewer）
4. 协作者立即获得对应权限

**权限矩阵**：

| 操作 | owner | editor | viewer |
|------|-------|--------|--------|
| 查看知识库 | ✅ | ✅ | ✅ |
| 上传/删除文档 | ✅ | ✅ | ❌ |
| 修改知识库配置 | ✅ | ❌ | ❌ |
| 管理协作者 | ✅ | ❌ | ❌ |
| 删除知识库 | ✅ | ❌ | ❌ |
| 聊天问答 | ✅ | ✅ | ✅ |
| 提交反馈 | ✅ | ✅ | ✅ |

#### 3.1.4 删除知识库

- 进入知识库 → 设置 → 危险操作 → 删除知识库
- 需要输入知识库名称确认
- 30 天内可在"回收站"恢复
- 超过 30 天永久删除（包括向量数据）

### 3.2 文档管理

#### 3.2.1 上传文档

1. 进入知识库 → 文档标签
2. 点击 **上传文档** 或直接拖拽文件到上传区域
3. 支持的格式：

| 格式 | 扩展名 | 单文件大小限制 |
|------|--------|----------------|
| PDF | .pdf | 20 MB（可配置） |
| Word | .docx | 20 MB |
| Markdown | .md | 20 MB |
| 纯文本 | .txt | 20 MB |

4. 上传后文档状态流转：

```
pending → parsing → chunking → embedding → done
                                              ↘ failed
```

5. **进度查看**：上传后页面会实时显示解析进度（WebSocket 推送）

#### 3.2.2 文档预览

- 在文档列表点击文档名，可预览原文内容
- PDF 文档支持按页浏览
- Markdown 文档支持渲染后的预览
- 文档右侧显示分块信息（chunk 列表）

#### 3.2.3 文档状态说明

| 状态 | 含义 | 处理建议 |
|------|------|----------|
| pending | 等待解析 | 等待 Celery Worker 接管 |
| parsing | 解析中（提取文本） | 通常 1-10 秒 |
| chunking | 分块中 | 通常 1-5 秒 |
| embedding | 向量化中（调 Ollama） | 大文档可能数分钟 |
| done | 解析完成，可用于问答 | 正常 |
| failed | 解析失败 | 查看错误信息，重新上传或联系管理员 |

#### 3.2.4 删除文档

- 文档列表 → 操作列 → 删除
- 软删除（30 天可恢复）
- 同时清理 Qdrant 向量数据

#### 3.2.5 批量操作

- 多选文档后可批量删除 / 重新解析

---

### 3.3 聊天对话

#### 3.3.1 新建会话

1. 进入 **聊天** 页面
2. 点击 **+ 新建会话**
3. 选择关联的知识库（可多选）
4. 输入会话标题（可选，默认根据首个问题自动生成）

#### 3.3.2 流式响应

- 输入问题后按回车或点击发送
- 系统通过 SSE（Server-Sent Events）流式返回：
  1. **searching** 事件：正在检索知识库
  2. **delta** 事件：逐 token 输出答案
  3. **done** 事件：回答完成，附带 message_id
- 答案下方显示 **引用来源**：
  - 来源文档名
  - 命中段落原文
  - 相关度评分

#### 3.3.3 引用查看

- 每个引用块显示：
  - 文档标题（点击可跳转到文档预览）
  - 命中的文本片段
  - 相似度分数（0-1）
- 可点击"展开"查看更多上下文

#### 3.3.4 会话管理

- 左侧会话列表支持搜索、置顶、重命名、删除
- 历史消息完整保留（除非主动删除会话）
- 支持导出会话为 Markdown 文件

#### 3.3.5 上下文管理

- 默认携带同一会话最近 5 轮对话作为上下文
- 可在会话设置中调整上下文窗口长度

### 3.4 评估系统

#### 3.4.1 创建评估任务

1. 进入 **评估** 页面（仅 admin / editor 可见）
2. 点击 **+ 创建评估**
3. 配置：

| 字段 | 说明 | 默认 |
|------|------|------|
| 知识库 | 待评估的 KB | — |
| 题目数量 | 评估题目数 | 5 |
| 题目来源 | 自动生成 / 手动导入 | 自动 |
| 评估指标 | RAGAS 4 项 | 全选 |

4. 点击 **开始评估**
5. 任务进入 Celery 异步执行（约 4 分钟/题，CPU 环境）

#### 3.4.2 查看评估报告

- 任务完成后，点击任务行查看详细报告
- **总体得分**：4 项指标的平均分
- **单题详情**：每道题的答案、引用、各指标得分
- **趋势图**：历史评估对比（折线图）

#### 3.4.3 RAGAS 指标说明

| 指标 | 含义 | 计算方式 | 目标 |
|------|------|----------|------|
| **faithfulness**（忠实度） | 答案是否忠于引用来源 | LLM 评估答案与上下文一致性 | > 0.9 |
| **answer_relevancy**（答案相关性） | 答案是否切题 | LLM 反向生成问题与原问题相似度 | > 0.8 |
| **context_precision**（上下文精度） | 检索结果中相关内容的占比 | 命中段落中相关段落数 / 总命中段落 | > 0.7 |
| **context_recall**（上下文召回） | 答案是否覆盖了所有相关上下文 | 答案覆盖的上下文信息 / 全部相关上下文 | > 0.8 |

#### 3.4.4 评估结果解读

- **绿色**：达标（>0.8）
- **黄色**：一般（0.5-0.8）
- **红色**：不达标（<0.5）

**改进建议**：

- 忠实度低 → 检查 LLM 模型与 prompt
- 相关性低 → 检查 query 改写
- 精度低 → 调整 top_k / rerank 模型
- 召回低 → 调整 chunk_size / 增加 embedding 维度

### 3.5 反馈系统

#### 3.5.1 提交反馈

- 在聊天回答下方，点击 👍 / 👎
- 可填写评论（可选）
- 反馈立即入库，影响评估指标

#### 3.5.2 查看反馈统计

进入 **反馈** 页面（仅 admin 可见）：

- **正反馈率**：7/30/90 天正反馈占比（折线图）
- **类型分布**：点赞 vs 点踩（环形图）
- **热力图日历**：每日反馈数量
- **详细列表**：每条反馈的内容、对应消息、用户

#### 3.5.3 反馈应用

- 反馈数据用于：
  - 评估 RAG 质量趋势
  - 定位低质量回答（点踩队列）
  - 优化 prompt 与检索参数

### 3.6 用户管理（管理员）

> 仅 admin 角色可见

#### 3.6.1 用户列表

- 进入 **用户管理** 页面
- 显示所有用户：用户名、邮箱、角色、创建时间、最近登录、状态

#### 3.6.2 创建用户

1. 点击 **+ 新建用户**
2. 填写：用户名、邮箱、密码、角色（admin / editor / viewer）
3. 用户可立即登录

#### 3.6.3 修改用户角色

- 用户列表 → 操作 → 修改角色
- 支持降级与升级

#### 3.6.4 禁用 / 删除用户

- **禁用**：用户无法登录，但数据保留
- **删除**：永久删除用户，所有知识库 owner 转移给 admin

#### 3.6.5 重置密码

- 用户列表 → 操作 → 重置密码
- 系统生成临时密码，用户首次登录后必须修改

### 3.7 系统监控（管理员）

> 仅 admin 角色可见

#### 3.7.1 监控入口

| 监控工具 | 入口 | 用途 |
|----------|------|------|
| Grafana | http://<server>:3000 | 仪表板可视化 |
| Prometheus | http://<server>:9090 | 指标查询与告警状态 |
| Jaeger | http://<server>:16686 | 分布式追踪 |
| Flower | http://<server>:5555 | Celery 任务监控 |
| Alertmanager | http://<server>:9093 | 告警路由 |

#### 3.7.2 Grafana 仪表板

预置两个仪表板：

1. **RAG 平台总览**：14 个面板
   - API 请求量 / 错误率 / 响应时间
   - RAG 检索次数 / 命中率
   - 活跃会话数 / 用户数
   - DB 连接池使用率
   - LLM 推理耗时 / 首 token 延迟
   - 文档处理状态分布
2. **Celery 任务详情**：
   - 任务队列长度
   - 任务执行时间
   - Worker 状态
   - 失败任务统计

#### 3.7.3 告警规则

平台预置 11 条告警规则，告警通过 Alertmanager 路由到 webhook receiver：

- **Critical 级别**：5xx 错误率 / 内存使用 / DB 连接池 / 30 分钟无流量 / Redis 内存
- **Warning 级别**：CPU / 磁盘 / KB 创建异常 / 文档解析失败率 / 聊天 P95 慢 / LLM 推理超时

#### 3.7.4 日志查询

通过 Grafana → Explore → Loki 查询容器日志：

```logql
{container="aiplatform-backend-1"} |= "ERROR"
{container="aiplatform-celery_worker-1"} |= "document"
```

#### 3.7.5 追踪查询

通过 Jaeger UI 查询分布式追踪：

- Service：`rag-platform-backend`
- Tags：`http.status_code=500` 查找错误请求
- 与日志通过 `trace_id` 关联

## 4. Tauri 桌面客户端使用

### 4.1 安装

1. 获取安装包 `RAG 知识库平台_0.2.0_x64-setup.exe`
2. 双击运行安装程序
3. 默认安装路径：`C:\Program Files\RAG 知识库平台\`
4. 安装完成后桌面会出现快捷方式

### 4.2 启动与登录

- 双击桌面图标启动
- 应用窗口自动打开，显示登录页
- 输入账号密码登录后进入主界面

### 4.3 窗口管理

| 操作 | 效果 |
|------|------|
| 点击窗口右上角 **×** | 最小化到系统托盘（不退出） |
| 点击托盘图标 | 显示/隐藏主窗口 |
| 双击托盘图标 | 显示主窗口 |
| 托盘菜单 → 显示 | 显示主窗口 |
| 托盘菜单 → 退出 | 完全退出应用 |
| 单实例锁 | 已运行时再次启动会激活原窗口 |

### 4.4 系统托盘

托盘菜单项：

- **显示**：显示主窗口
- **退出**：完全退出应用

托盘图标说明：
- 蓝色：正常运行
- 灰色：网络异常或未登录

### 4.5 深度链接（Deep Link）

支持 `rag-platform://` 协议：

| 链接 | 行为 |
|------|------|
| `rag-platform://login` | 打开登录页 |
| `rag-platform://chat/session/{id}` | 跳转到指定会话 |
| `rag-platform://kb/{id}` | 跳转到指定知识库 |

**使用方法**：
- 在浏览器或邮件中点击 `rag-platform://...` 链接
- 系统自动唤起桌面客户端并跳转到对应页面

### 4.6 全局快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+Shift+R` | 全局唤起/显示主窗口（无论当前焦点在何处） |

> 快捷键在应用运行时全局生效，即使窗口最小化到托盘也可触发。

### 4.7 自动更新

- 应用启动时自动检查 GitHub Releases 是否有新版本
- 有新版本时弹出更新提示对话框
- 用户确认后下载并安装，应用自动重启
- 更新文件由发布公钥签名验证，确保完整性

### 4.8 CDP 调试（开发者）

如需调试 Tauri 内部 WebView：

1. 应用启动后，访问 `http://localhost:9223/json`
2. 在 Chrome 浏览器中打开 `chrome://inspect`
3. 配置 `localhost:9223` 端口
4. 点击 "inspect" 打开 DevTools

### 4.9 与 Web 端的差异

| 维度 | Web 端 | Tauri 桌面端 |
|------|--------|--------------|
| 入口 | 浏览器 URL | 桌面应用 |
| 离线 | 不支持 | 部分支持（缓存页面） |
| 通知 | 浏览器通知 | 系统托盘通知 |
| 快捷键 | 浏览器内 | 全局快捷键 |
| 深度链接 | 不支持 | 支持 `rag-platform://` |
| 自动更新 | 需手动刷新 | 自动检查并更新 |
| 资源占用 | 浏览器共享 | 独立 WebView2 进程 |

## 5. 常见问题 FAQ

### 5.1 登录相关

**Q：忘记密码怎么办？**
A：联系管理员重置密码。管理员可在"用户管理"页面生成临时密码。

**Q：登录后提示 "Token has expired"？**
A：access_token 默认 30 分钟过期，请使用 refresh_token 自动刷新，或重新登录。

**Q：登录后页面空白？**
A：检查浏览器控制台是否有 CORS 错误，确认 `deploy/.env` 中 `CORS_ORIGINS` 包含当前访问域名。

### 5.2 文档上传

**Q：上传 PDF 后一直 "parsing" 状态？**
A：检查 Celery Worker 是否正常运行（Flower UI: http://<server>:5555）。如 Worker 异常，重启 celery_worker 容器。

**Q：上传 DOCX 失败？**
A：确认文件未损坏，且扩展名为 `.docx`（不支持旧版 `.doc`）。

**Q：上传文件提示 "413 Request Entity Too Large"？**
A：文件超过 Nginx `client_max_body_size` 限制（默认 50MB）。修改 `deploy/nginx.conf` 并重启 nginx。

### 5.3 聊天问答

**Q：聊天响应很慢（>30 秒）？**
A：
- CPU 环境：确认使用 `qwen2.5:1.5b` 小模型
- 检查 Ollama 容器 CPU 使用率（docker stats）
- 考虑部署 GPU 环境或切换云端 API

**Q：聊天返回 "no chunks found"？**
A：知识库中可能没有相关文档，或文档尚未解析完成。检查：
1. 知识库中是否有 status=done 的文档
2. 问题是否与文档内容相关
3. top_k 参数是否过小

**Q：引用来源显示乱码？**
A：可能是 PDF 解析时编码问题。尝试重新上传，或转换为 Markdown 格式。

### 5.4 评估

**Q：评估任务一直 "running"？**
A：CPU 环境下 RAGAS 评估耗时较长（约 4 分钟/题）。可在 Flower 查看任务进度。若超过 30 分钟未完成，检查是否 Ollama 超时。

**Q：RAGAS 指标全部为 0？**
A：
- 确认 Ollama 模型已加载
- 检查 LLM_PROVIDERS_JSON 配置
- 查看 backend 日志是否有 LLM 调用错误

### 5.5 Tauri 客户端

**Q：安装时被 Windows Defender 拦截？**
A：当前版本未做代码签名，需要在 Windows 安全设置中添加例外，或使用 Authenticode 签名证书。

**Q：启动后窗口空白？**
A：检查 WebView2 Runtime 是否安装（Windows 11 默认已装）。下载地址：https://developer.microsoft.com/microsoft-edge/webview2/

**Q：深度链接点击无反应？**
A：首次安装后协议可能未注册，重启应用或重启系统。

**Q：自动更新失败？**
A：检查网络是否能访问 `https://github.com`，以及 `tauri.conf.json` 中 `pubkey` 与发布私钥是否匹配。

### 5.6 性能

**Q：API 响应慢？**
A：参考 v0.2.0 性能基准：
- API P95 应在 11-38ms
- 登录 P95 ~587ms（bcrypt 哈希正常开销）
- 如超出，查看 Prometheus `rag_http_request_duration_seconds` 指标

**Q：磁盘空间增长快？**
A：
- Docker 日志：配置 `json-file` 日志轮转
- Loki 数据：调整 retention
- PostgreSQL：执行 VACUUM
- 备份文件：定期清理过期备份

### 5.7 监控告警

**Q：收到 "HighErrorRate" 告警？**
A：
1. 查看 Grafana 错误率面板
2. 在 Loki 查询 `|= "ERROR"` 日志
3. 在 Jaeger 通过 `http.status_code=500` 查找错误 trace
4. 根据错误信息定位代码

**Q：收到 "LLMInferenceTimeoutP99" 告警？**
A：LLM 推理 P99 > 120 秒。
- CPU 环境：考虑升级到 GPU 或换更小模型
- 检查 Ollama 容器资源使用率
- 考虑增加 `OLLAMA_NUM_PARALLEL` 并发数
